# Finite Production CaseGraph v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `CASE_ANALYSIS_NOT_READY` with a finite, typed Case Analysis workflow that ends in bounded clarification or a non-executing evidence-request skeleton.

**Architecture:** `decision_support/` remains the source of every domain rule; `agent/case_graph.py` composes the existing typed capabilities in an acyclic LangGraph and `AssistantService` maps terminal state without changing `AgentService`. The API adds one optional sanitized `case_analysis` projection while all direct-QA fields remain unchanged.

**Tech Stack:** Python 3.11, Pydantic v2, LangGraph, FastAPI, pytest/pytest-asyncio, Ruff, Pyright.

**Spec:** `docs/superpowers/specs/2026-08-29-casegraph-v1-1-design.md`

## Global Constraints

- Production code remains under `src/vietnamese_labor_law_assistant/` with absolute package imports.
- `decision_support/` owns intake, missing-fact, clarification, refinement, and evidence-request rules; `agent/` owns finite orchestration only.
- `AssistantService` retains `DIRECT_QA -> AgentService`, `CASE_ANALYSIS -> CaseGraph`, and `OUT_OF_SCOPE -> bounded refusal`; `AgentService` is not edited.
- A Case Analysis request makes one call to the existing `CaseIntakeExtractor`; its existing bounded retry policy is unchanged.
- Case Analysis makes zero MCP, retrieval, and calculator calls and emits no legal outcome, recommendation, or application narrative.
- Any missing required fact terminates the current request as `CLARIFICATION_REQUIRED`; there is no loop, checkpointer, or case memory.
- Do not create `evidence_plan.py`, an `EvidencePlan`, a new MCP server, frontend components, release evidence, or future-week rules.
- Keep `R2_H2_C10_O5_L512_B1`, protected artifacts, `AgentIntent`, and `WorkflowStatus` unchanged.
- Tests are offline and use injected Case Intake stubs.

- [ ] **Step 4: Implement the five acyclic nodes**

Implement `build_case_graph(...)` with these node names and routes:

```text
START -> case_intake
case_intake -> detect_missing_facts | END
detect_missing_facts -> build_clarification | refine_issues | END
build_clarification -> END
refine_issues -> build_evidence_request | END
build_evidence_request -> END
```

`CaseGraph.__init__` requires a `CaseIntakeExtractor` and accepts optional concrete domain
capabilities for offline fault injection. Each node catches only its bounded failure, records a
typed safe terminal, and never copies requirement policy into `agent/`. `CaseGraph.run` wraps an
unexpected graph exception as `CASE_ANALYSIS_FAILED` without serializing `str(exc)`.
